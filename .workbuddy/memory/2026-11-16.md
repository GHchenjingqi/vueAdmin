## 修复：前台「后台管理」点击无反应（根因 tryRestorePath 覆盖用户导航）
- 现象：已登录时在前台 `/portal/prompts` 点顶栏「后台管理」，URL 与页面完全不变；未登录时却能正常跳 `/login`。
- 用 Playwright 无头浏览器给 `history.pushState/replaceState` 打桩，抓到点击后的调用序列：`push → /dashboard`、`replace → /portal/prompts`，即导航本身生效，随后被强制拉回前台。
- 根因：`src/router/dynamicRoutes.ts` 的 `tryRestorePath()` 无条件 `router.replace(savedPath)`；App.vue 的 `restoreSession()` + `menuStore.fetchMenus()` 在云端较慢，这次 replace 晚于用户点击执行。且 `savedPath` 只含 pathname，会把 URL 上的 `sharecode` query 抹掉（复现中前台 URL 的 sharecode 确实消失）。
- 修复：`tryRestorePath()` 改为仅当 `router.currentRoute.value.name === 'NotFound'`（刷新后动态路由尚未注册的暂态）才恢复；已正确落在页面或用户已主动导航离开时直接 return false。仅改这一个文件，`npm run typecheck` 通过。
- 重新构建 → 同步 `prompt-cloud/client/` → 经用户确认重新发布，链接不变。线上复测全通：前台点「后台管理」→ `/dashboard` 且仪表盘渲染正常；前台 URL 保留 sharecode；后台顶栏「提示词广场」→ 前台正常；刷新 `/prompt-categories` 动态路由仍显示分类管理（非 404）。
- 排障技巧：Vue3 生产构建下可从 `document.querySelector('#app').__vue_app__.config.globalProperties.$router` 取得 router 实例，用 `getRoutes()` / 手动 `push()` 区分「链接没触发导航」与「导航被回滚」。
- 遗留（与本次无关）：云端 stub 未实现 `/api/v1/ai/providers/enabled`、`/api/v1/ai/status`，控制台有 404 噪音；SSE 连接会 ERR_ABORTED，均不影响功能。
