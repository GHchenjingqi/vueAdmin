## 重大发现：全局租户 beforeFind 钩子对「读」不生效（已修）
- 根因：`server/modules/tenant/hooks/sequelizeTenantScope.ts` 的 `beforeFind` 用 `sequelize.addHook`（全局钩子），但 Sequelize 全局 beforeFind 触发时 `options.model` 为 undefined，导致 `if (!Model?.rawAttributes?.tenantId) return` 永远 early-return，**读查询从不注入租户过滤**。验证：tenant=1 写、tenant=999 读仍返回 tenant=1 数据。
- 对比：billing 模块读查询是**显式在 where 带 tenantId**（从 controller 传入），knowledge 模块则未做租户隔离（无 tenantId 列）。即项目惯例是「租户隔离在 service/controller 显式做」，全局钩子只是失效的安全网。
- 修复（局部、不碰框架）：shop 7 个 service 的**写**在 create/upsert 显式注入 `tenantId=getTenantContext()?.tenantId ?? 1`；**所有读**（find/findOne/count/destroy，含状态机/删除内部查询）where 显式加 `tenantId`。验证 tenant=999 读隔离为 0 行、tenant=1 读为 1 行。
- 提交 `1eb2daf` 含：补提交阶段1漏掉的 7 张表迁移（000002-000008，之前只提交了 seed 迁移 000001/000009，会导致新 clone 迁移失败）+ 上述租户隔离修复。
- 注：框架级全局钩子缺陷仍存在（影响其他读路径），属存量 infra 问题，超出本次 shop 任务范围；如需全局修复可后续评估在 `registerTenantScope` 改为按模型注册钩子。

## 重大发现：validate 中间件会剥离未声明的 query 参数（已修）
- 根因：`server/middleware/validate.ts` 用 `schema.parse(req[target])` 后**整体替换** `req.query`；Zod 默认剥离未在 schema 声明的字段。`shopPaginationSchema` 只声明了 page/pageSize/keyword，导致所有列表接口的专属筛选参数（skuId / warehouseId / spuId / channelId / shopId / status / type / categoryId / dimension）**全部丢失**，接口静默返回全量数据（不报错，最难发现的一类缺陷）。
- 修复（两步）：① `shopPaginationSchema` 加 `.passthrough()` 保留未声明参数；② 新增 `server/modules/shop/utils/query.ts`（`queryInt` / `queryStr`），把各 controller 里裸的 `Number(req.query.x)` 换成 `queryInt(req.query.x)`，非法值一律视为「未传」，避免 NaN 进 Sequelize where；service 层再对 status/type 等枚举加白名单。
- 复盘教训：任何用 `validate(schema,'query')` 的路由，若 schema 未 `.passthrough()`，则该 schema 未声明的 query 参数会被静默吞掉 —— 加筛选参数时必须同步扩 schema。

## Git 排错：Windows 上 Git 对非 ASCII 文件名产生 `??` 幽灵条目
- 现象：`shops/mds/跨境独立站开发执行计划_v1.0.md` 提交后，`git status` 同时出现 `A`（已暂存）与 `??`（未跟踪）同名的幽灵条目；`git mv` 改名、reset、重新 add 都无法消除，实际磁盘上已无此中文名文件（仅存改名后的 ASCII 文件）。根因是 Windows/msys Git 对该特定非 ASCII 文件名的目录扫描规范化（NFC/NFD）幽灵。
- 规避（已验证有效）：① 回退索引到远程干净态 `git reset origin/master_shop`（保留工作树文件，--mixed）；② 把该文档改名为 **ASCII 文件名**（`storefront-execution-plan_v1.0.md`）后，仅显式 `git add` 真实文件（不含幽灵名）再提交。提交树干净、不携带幽灵；**幽灵 `??` 是本地显示问题，不会进入提交树、不随推送传播**，远程 clone 不受影响。
- 结论：本仓库内**新增文档/文件名尽量用 ASCII**；若必须中文名且出现幽灵，改用 ASCII 文件名规避。之前已提交的中文名文件（如 `独立站前端架构与功能设计.md`）未触发幽灵，属个案。
- 注：`git commit` 时 husky/lint-staged 会打印 `→ No staged files match any configured task.`（无匹配任务），但提交仍成功，可忽略。
