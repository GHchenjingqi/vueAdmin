## 第三轮：管理端越权（后端授权缺失）— 已修复并推送 `d196143`

第三轮聚焦「租户隔离 + 账号安全」。子代理派发遇 429 限流，改为自行定向审查 + **运行时实测取证**。

### 根因
管理端后端**只做认证不做授权**：`authMiddleware` 仅校验登录态，按钮级权限完全依赖前端 `v-permission`（`display:none` 隐藏按钮）。全仓无 `checkPermission`/`hasPermission` 中间件。

### 实测取证（低权用户 dataScope=2 / isPlatformAdmin=false，逐条独立成立）
| 路径 | 修复前 | 危害 |
|---|---|---|
| `PATCH /users/:id/password` {reset:true} | **200** | 重置 admin 密码 → 完整账号接管 |
| `PUT /users/:id` {roleIds:[platform_admin]} | **200** | 自我提权为平台超管，绕过全部租户隔离 |
| `PUT /settings` | **200** | 改全局设置（含 captcha_enabled） |
| `POST /roles`（dataScope=1） | **201** | 自造全量可见角色 |
| `PUT/DELETE /roles/:id`（platform_admin） | **200** | 改写/删除超管角色 |
| `POST /menus` / `POST /departments` | **201** | 篡改权限体系与组织结构 |
| `DELETE /logs` | **200** | 清审计日志（掩盖痕迹） |
| `POST /notification-channels` | **200** | 写入通知凭据 |
已阻断：`DELETE /users/:id`（isTargetInScope 生效）、自改用户名 admin（DB 复合唯一）。

### 第二处越权（跨租户）
`authService.buildTokenPayload` 平台超管判定为 `username === 'admin'`，但 users 表用户名唯一性是 `(tenantId, username)` 复合唯一 → **任意租户创建名为 admin 的账号即成平台超管**，tenantContext 的 bypass 置 true → Sequelize 全局租户钩子失效 → 跨租户读写。已改为仅认 `platform_admin` 角色。

### 权限模型（与种子数据、前端 v-permission 对齐）
- `platform_admin` → 平台超管：跨租户；唯一可授予 platform_admin、唯一可改写 platform_admin 角色定义
- `admin`/`super_admin` → 全局管理员：可执行全部管理写操作、可授予 admin 级角色；无跨租户能力
- 其它 → 普通用户
注意：`roles` 表是**全局表**（code/name 全局唯一），故 `Role` 模型**不可**声明 `tenantId`——一旦声明，全局租户钩子会过滤掉其它租户共用的角色造成回归。（`menus`/`logs` 同为全局表。）
