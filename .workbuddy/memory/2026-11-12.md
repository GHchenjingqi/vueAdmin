## 追加：安全 / watch / 构建验收收口（10:20）

上文「未处理」前三项已全部收口，仅 staging/生产演练因缺环境保留。

- **私钥入库**：`server/utils/generateCert.ts` 的 `getOrCreateCert()` 本来就会在 key/crt 任一缺失时自动创建目录并生成 365 天自签证书，所以 `.cert/*.key` 入库纯属多余且是安全隐患。用 `git rm --cached .cert/server.key .cert/server.crt` 从版本库移除（**本地文件保留**，运行中的 5173 不受影响），`.gitignore` 加 `.cert/`，README 目录树与访问说明标注「本地生成、不入库、换机器需重新信任」。
- **自动生成实测**：把 `.cert/` 整体 mv 到 `%TEMP%/web-cert-20261112/` 后调 `getOrCreateCert()`，生成 1704B key + 1049B cert 且 PEM 合法；再把新生成目录移走、原目录 mv 回来，`sha256sum -c` 校验一致、文件时间戳未变。全流程只做移动、零删除。
- **dev watch**：没有把默认 `dev` 改成 `tsx watch`（会随改动重启定时任务/扫描器），而是新增可选脚本 `server/package.json` → `dev:watch: tsx watch app.ts`，README 说明每次重启会重跑 `bootstrap()` 并重建 DB/Redis 连接。默认行为零改动。
- **shops 真实构建（长期缺口，已破）**：历史记录说 `nuxt build` 被 safe-delete 拦截，根因是工作区已有 `.nuxt/dist` 需要在构建时清理。解法是**隔离源码副本**：`tar` 复制 shops（排除 node_modules / .nuxt / .output / .env）到 `%TEMP%/web-shops-build-20261112/shops`，用 PowerShell `New-Item -ItemType Junction` 把 259M 的 `node_modules` 链过去，副本无 buildDir → 无需任何删除。`npm run build` **exit 0**，产出 `.output/server/index.mjs`（3.21 MB）。
- **生产产物 SSR 验证**：`PORT=3100 NITRO_PORT=3100 NUXT_API_INSECURE_TLS=1 node .output/server/index.mjs` 启动，首页 200 / 1.03MB（含 `Recommended for You` 与 `__NUXT__`）、`/api/store-config` 200 返回 USD；原 dev 3000 仍 200，工作区无改动。
- **全量单测噪声**：`server/__tests__/shopPhases.test.ts` 销售报表用例在全量并发下实测 35.9s，30s 会误报超时；放宽到 60s 并订正注释。全量 **159/159 文件、1630/1630 用例全绿**（单跑约 13s，非逻辑缺陷）。
- **约定**：Windows 下给临时副本挂依赖用 `New-Item -ItemType Junction`（比复制 259M 快且零改动）；`nuxi build` 支持 `ROOTDIR` 参数，配合干净副本可绕开构建目录清理限制。
