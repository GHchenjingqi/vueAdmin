# M6 · 运营平台与交付

> 前置：M1-M5。这是商业化最后拼图：平台运营视角 + 私有化交付能力。

---

## 目标

1. 平台管理后台：租户列表/套餐/用量/计费/冻结/隔离校验（平台超管视角）。
2. 试用与 Onboarding：租户自助注册 + 试用套餐 + 引导向导。
3. 白标 / OEM：品牌/Logo/主题色/域名按租户定制。
4. License：私有化部署的离线授权（机器码绑定 + 到期 + 模块授权位）。
5. 交付三模式：SaaS / 私有化 / 混合，Helm Chart + 离线安装包。

周期：持续迭代，首发 2 周。

---

## 步骤 1：平台管理后台（前端拆壳）

### 1.1 前端拆分
新建 `src/views/platform/`（独立路由 `platformRoutes`，仅 `isPlatformAdmin` 可见）：
- `TenantList.vue`：租户列表（租户名/编码/套餐/状态/用量摘要/到期/冻结按钮）。
- `TenantDetail.vue`：租户详情（用量明细/订阅/计费/隔离校验结果）。
- `PlatformDashboard.vue`：平台总览（总租户数/活跃/收入/资源水位）。

`src/router/` 新增 `platformRoutes`，路由守卫校验 `userStore.isPlatformAdmin`，否则 403。

### 1.2 后端平台路由
`server/modules/platform/routes/platformRoutes.ts`，全部 `authMiddleware + platformAdminGuard + tenantContext(bypass=true)`：
```
GET    /platform/tenants
GET    /platform/tenants/:id
PUT    /platform/tenants/:id/status    -- 冻结/启用
PUT    /platform/tenants/:id/plan      -- 改套餐
GET    /platform/usage                 -- 全租户用量
GET    /platform/revenue               -- 收入统计
POST   /platform/tenants/:id/isolation-check  -- 校验该租户数据不被他人访问
```

`platformAdminGuard` 中间件：`req.user.isPlatformAdmin !== true` → 403。bypass 模式跨租户查询（M1 的 `runInTenant({bypass:true})`）。

### 1.3 租户隔离自检
`isolation-check`：抽测——构造 tenant A 的上下文尝试按 id 查 tenant B 的用户，必须返回空（验证全局 hook 生效）。结果写 audit。

## 步骤 2：试用与 Onboarding

### 2.1 自助注册租户
`server/modules/tenant/routes/tenantPublicRoutes.ts`（公开，无需登录）：
```
POST /tenants/register   -- { name, code, adminEmail, adminPassword }
```
流程：
1. 校验 code 唯一、adminEmail 格式、密码强度。
2. 开事务：建 Tenant(status=trial) + 建 platform_admin? 不，建租户管理员 User(tenantId=新id) + 绑 free 或 trial 套餐订阅。
3. 发激活邮件（M4 mail 队列）。
4. 前端注册页 `src/views/RegisterTenant.vue`。

### 2.2 试用套餐
trial 订阅 `currentPeriodEnd = now + 14天`，`maxUsers` 等按 trial 配置（plans 加 `trial` 档或复用 free 上浮）。到期后（M4 日聚合任务）自动转 free 或冻结，发到期通知。

### 2.3 Onboarding 向导
`src/components/OnboardingWizard.vue`：新租户首登弹窗，引导完成"建部门→建角色→建用户→配工作流"。复用现有页面，向导只做步骤索引。

## 步骤 3：白标 / OEM

### 3.1 租户级设置
`settings` 表（`server/models/Setting.ts`，key-value）扩展租户维度：
- 迁移 `20261005_000001_add-tenant-scope-to-settings.ts`：加 `tenantId BIGINT NULL`（NULL=全局默认，非 NULL=租户覆盖）。
- `settingController` 读时：先查租户级覆盖，无则回退全局。
- 全局 tenant hook 对 settings 表特殊处理：非平台超管查询自动带 `where (tenant_id = ? OR tenant_id IS NULL)`（需在 hook 里对 settings 表特判，或 service 层显式查两层）。

### 3.2 品牌
租户级 settings 种子/配置项：
```
site_name / site_logo / site_favicon / primary_color / custom_domain
```
`siteStore`（前端）按当前租户加载这些覆盖项，动态注入到 `App.vue`（已有 siteInfo 注入雏形，扩展为按租户）。

### 3.3 自定义域名
`custom_domain` → Nginx/Ingress 按 Host 头路由到对应租户上下文；后端在请求入口按 Host 解析 tenantId 注入（与 JWT 路径并列，用于未登录页如登录页/注册页的品牌呈现）。

## 步骤 4：License（私有化专用）

### 4.1 模型与签发
`server/modules/license/`：
- 离线签名：平台用 RSA 私钥签发 license，私有化部署用内置公钥验签。
- license payload：`{ tenantName, machineCode, expiresAt, modules: ['bpm','lowcode','openapi'], maxUsers }`。
- 机器码 = `sha256(CPU序列号 + 主板UUID + MAC)`，启动时采集并与 license 内 machineCode 比对。

### 4.2 校验
`server/modules/license/middleware/licenseGuard.ts`（启动期执行一次 + 定期校验）：
- 无 license 或校验失败 → 启动报错或降级为社区版（按 `DEPLOY_MODE` 决定是否硬性拦截）。
- 模块授权位：未授权模块（如 bpm）相关路由返回 403 + "需企业版授权"。

### 4.3 签发工具
`server/scripts/issue-license.ts`（CLI，平台侧离线运行）：`node dist/scripts/issue-license.js --tenant X --machine Y --days 365 --modules bpm,lowcode`。

## 步骤 5：交付三模式

### 5.1 部署模式开关
`server/config/index.ts`：`DEPLOY_MODE = saas | onprem | hybrid`。
- `saas`：多租户共享，启用平台后台、计费、试用注册。
- `onprem`：单租户，启用 License 校验，关闭平台后台与计费（或保留只读）。
- `hybrid`：数据本地 + 控制面云端（留接口，首发可仅文档）。

### 5.2 Helm Chart
基于现有 `k8s/`（Kustomize）封装 Helm：
- `deploy/helm/vue-admin/`：`Chart.yaml`、`values.yaml`（含 DEPLOY_MODE、licenseSecret、storage provider、replicas）。
- 区分 web Deployment 与 worker Deployment（M4 的 worker 进程）。
- 私有化交付：`helm template` 出离线 manifest，或连同镜像打离线包。

### 5.3 离线安装包
`deploy/offline/`：脚本 `build-offline.sh/.ps1` → `docker save` 镜像 + 镜像加载脚本 + `install.sh/.ps1`（依赖检查 → 导入镜像 → 渲染配置 → 启动）。README 附"私有化部署手册"。
