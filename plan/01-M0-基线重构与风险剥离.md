# M0 · 基线重构与风险剥离

> 前置：无。这是整个商业化升级的第一步，目的是在引入多租户前把安全风险与开发态能力隔离干净。

---

## 目标

1. 把 AI 代码生成助手（含文件写入/菜单创建）隔离为默认关闭、仅平台超管可用的能力。
2. 服务监控从租户可见菜单中移除，降级为平台运维视角。
3. 生产环境禁止使用自签名证书启动。
4. 收敛数据库账号：生产禁止 root 直连 + 自动建库。

周期：1 周。不改业务模型，只做开关与校验。

---

## 步骤 1：AI 助手隔离

### 背景
`server/services/CodeInjector.ts` 可任意写文件 + 创建菜单，在多租户 SaaS 中等于"租户能向系统注入代码"，是严重供应链攻击面。M0 先做隔离不删代码。

### 修改文件
- `server/services/AIAssistant.ts` / `CodeInjector.ts`：所有写入/应用入口前置守卫，读取环境变量 `AI_INJECTOR_ENABLED`（默认 `false`），未启用时直接抛 `403 AI 代码注入已被禁用`。
- `server/routes/ai.routes.ts`：文件应用类接口（`/ai/apply` 等）在路由层增加 `requirePlatformAdmin` 守卫（M0 可暂用现有超管判断；正式守卫见 M1/M6）。
- `server/routes/index.ts:25`：`aiRoutes` 改为按配置条件挂载：
  ```ts
  if (config.app.aiAssistantEnabled !== false) {
    router.use(aiRoutes)
  }
  ```
- `.env.example`（根目录与 `server/.env.example`）：新增 `AI_INJECTOR_ENABLED=false` 并加注释"生产默认关闭，仅平台超管开启"。
- 前端 `src/components/AIAssistant/index.vue`：应用代码文件按钮根据后端 `/ai/status` 返回的 `injectorEnabled` 字段决定显隐。

### 验证
- `AI_INJECTOR_ENABLED` 不设或为 false 时，`POST /api/v1/ai/apply` 返回 403。
- 设为 true 时恢复正常。

## 步骤 2：服务监控降级

### 修改文件
- `server/routes/index.ts`：定位 `serverController` 相关路由（在线用户/服务监控/定时任务），给服务监控路由加 `platformOnly` 标记（M0 用注释 + 权限码占位，M1 接入 tenantContext 后正式拦截）。
- 前端：从默认菜单种子 `server/seeders/20260707_000004_default_menus.cjs` 中，将"服务监控"菜单设为 `hidden=1` 或迁移到平台菜单组（M6 落地正式平台后台前，先隐藏）。
  - 新增迁移 `server/migrations/20260901_000001_hide-server-monitor-menu.ts`：`UPDATE menus SET hidden=1 WHERE path='/server-monitor'`（用 query，遵循迁移规范）。

### 验证
- 普通租户侧边栏看不到"服务监控"。
- 接口仍可由超管直接调用（M6 再做正式平台后台收口）。

## 步骤 3：生产环境证书校验

### 修改文件
- `server/bootstrap.ts`：在启动监听前增加校验：
  ```ts
  if (config.app.nodeEnv === 'production' && config.app.useSelfSignedCert) {
    throw new Error('生产环境禁止使用自签名证书，请配置正式证书或反代 TLS')
  }
  ```
- `server/config/index.ts`：新增 `useSelfSignedCert` 读取项，默认 true（开发）；生产由 `NODE_ENV=production` 触发校验。
- `server/utils/generateCert.ts`：仅在 `useSelfSignedCert=true` 时生成。

### 验证
- `NODE_ENV=production` 且未配置正式证书时，启动直接抛错退出。
- 开发模式不受影响。

---

## 步骤 4：数据库账号收敛

### 修改文件
- `server/utils/ensureDatabase.ts`：`CREATE DATABASE IF NOT EXISTS` 仅在 `config.app.nodeEnv !== 'production'` 时执行；生产环境要求库已存在，否则抛错并提示"生产环境需预先建库"。
- `server/.env.example`：注释明确 `DB_USER` 生产应为受限业务账号（仅有目标库的 CRUD 权限，无 CREATE/SUPER）。
- `README.md` 部署章节：补"生产环境 DB 账号不得为 root"。

### 验证
- 生产环境若库不存在，启动报清晰错误而非自动建库。
- 开发环境仍自动建库（行为不变）。
