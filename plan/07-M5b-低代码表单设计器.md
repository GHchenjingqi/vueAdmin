# M5b · 低代码表单设计器

> 前置：M1 多租户、M5a 工作流（表单可绑定流程）。可与 M5a/M5c 并行。

---

## 目标

让企业客户不写代码搭出轻量业务模块（OA/CRM 场景）：
1. 业务对象（BusinessObject）定义：字段元数据 → 动态生成数据表或共享宽表存储。
2. 表单设计器：可视化配置表单 schema，复用现有 `ProForm`。
3. 列表页配置化：复用现有 `ProTable`/`CrudPage` 渲染。
4. 表单可绑定工作流（M5a）走审批。

周期：2 周。

---

## 步骤 1：数据模型设计决策

两种存储方案，M5b 采用 **共享宽表 + 动态字段 JSON**（落地快、零迁移建表）：

```
business_objects     元定义（对象名/字段列表/列表列配置）
business_records     数据行（objectId + data JSON + tenantId）
```
> 大客户需独立物理表可在后续提供"生成专用表"能力，M5b 不做。

---

## 步骤 2：迁移

`server/migrations/`：
```
20260928_000001_create-business-objects.ts
20260928_000002_create-business-records.ts
```

### business_objects（带 tenantId）
```
id PK AI
tenantId    BIGINT UNSIGNED  INDEX
code        VARCHAR(50)       -- 对象编码（如 customer/leave）
name        VARCHAR(100)
fields      JSON   -- [{prop,label,type,required,options,...}] 复用 ProForm schema
columns     JSON   -- 列表列定义 复用 ProTable columns
searchFields JSON
formLayout  JSON   -- 分栏/分组
status      TINYINT
UNIQUE(tenantId, code)
```

### business_records（带 tenantId）
```
id PK AI
tenantId   BIGINT UNSIGNED  INDEX
objectId   BIGINT UNSIGNED  INDEX
data       JSON
createdBy  BIGINT UNSIGNED
createdAt/updatedAt
INDEX(tenantId, objectId)
```

## 步骤 3：模型与 Service

`server/modules/lowcode/models/`：`BusinessObject.ts`、`BusinessRecord.ts`。
`server/modules/lowcode/services/lowcodeService.ts`：
- CRUD 业务对象定义（仅租户内）。
- 记录 CRUD：`listRecords(objectId, query)` 按 data JSON 内字段过滤（MySQL `JSON_EXTRACT`）。
- 导出（复用 `exportExcel.ts`，按 columns 配置导出）。

---

## 步骤 4：路由

`server/modules/lowcode/routes/lowcodeRoutes.ts`：
```
GET    /lowcode/objects
POST   /lowcode/objects              创建对象定义
PUT    /lowcode/objects/:id
DELETE /lowcode/objects/:id
GET    /lowcode/objects/:id/records  分页查询记录（支持 data 字段筛选）
POST   /lowcode/objects/:id/records
PUT    /lowcode/records/:id
DELETE /lowcode/records/:id
```
全部经 `authMiddleware → tenantContext`，记录查询受全局 tenant hook 隔离。

---

## 步骤 5：前端表单设计器

`src/views/lowcode/`：
- `ObjectList.vue`：业务对象列表（用现有 `CrudPage`）。
- `ObjectDesigner.vue`：可视化设计器
  - 左侧字段组件库（拖拽：input/select/date/switch/textarea/...）。
  - 中间画布渲染 `ProForm` 预览。
  - 右侧属性面板（字段属性、必填、选项）。
  - 输出 `fields` JSON 存入 business_objects。
- `RecordList.vue`：给定 objectId，用 `business_objects.columns` 渲染 `ProTable`，`fields` 渲染新增/编辑 `ProForm` 表单弹窗（复用 `useCrud`）。
- `RecordPage.vue`：动态路由 `/lowcode/data/:code`，按 code 查对象定义 → 渲染 RecordList。

`src/api/lowcode.ts` 对接。

> 动态菜单：业务对象保存时可自动注册一条菜单（path=`/lowcode/data/:code`），复用 M0 收口的菜单创建（但需租户级，非 AI 注入）。

---

## 步骤 6：表单绑定工作流

复用 M5a 的 `WorkflowBinding`（流程-业务单据绑定）：
- 触发对象从工作流固定业务扩展为 lowcode 对象。
- `WorkflowBinding` 加 `objectCode` 字段（迁移）。
- lowcode 记录"提交"时若绑定流程则触发实例，记录 id 作为 businessKey。
