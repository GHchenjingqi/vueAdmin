# M4 · 合规 / 存储 / 异步队列

> 前置：M1 多租户已完成（依赖 tenantId）。建议在 M2/M3 之后，因其依赖计费/SSO 的稳定基础。

---

## 目标

1. 审计日志增强：敏感操作前后快照、登录审计独立、合规导出。
2. 文件存储抽象：本地 / S3 / OSS / COS / MinIO 可切换，按租户配置。
3. 分布式任务队列：用 BullMQ（基于已有 Redis）替换 `node-cron` 进程内调度，解决多实例重复执行。
4. 密钥轮转：JWT 支持新旧双验签期。

周期：3 周。完成满足中大客户合规与运维诉求。

## 步骤 1：审计日志增强

### 1.1 迁移
`server/migrations/20260920_000001_create-audit-logs.ts`：
```
audit_logs:
id PK AI
tenantId     BIGINT UNSIGNED  INDEX
userId       BIGINT UNSIGNED
action       VARCHAR(100)    -- user.create / user.delete / data.export ...
module       VARCHAR(50)
targetType   VARCHAR(50)

afterSnapshot  JSON          -- 变更后快照

message      VARCHAR(500)
createdAt    DATETIME
INDEX(tenantId, action), INDEX(tenantId, userId), INDEX(createdAt)
```

### 1.2 模型
`server/modules/audit/models/AuditLog.ts`（带 tenantId）。

### 1.3 审计捕获中间件
`server/modules/audit/middleware/auditCapture.ts`：
- 包装 `res.json` / `res.end`，在写操作（POST/PUT/PATCH/DELETE）成功后异步写 audit_logs。
- `beforeSnapshot`：在 controller 查询目标记录后由显式调用 `captureBefore(instance)` 获取；无目标则跳过。
- `afterSnapshot`：取响应 data。
- 敏感操作白名单（用户增删改、角色权限变更、设置变更、数据导出、强制下线）。

挂载：`routes/index.ts` 在 `tenantContext` 之后挂 `auditCapture`。

### 1.4 登录审计独立
从现有 `logs` 表（`server/models/Log.ts`，type=login）的逻辑抽出，统一写入 `audit_logs`（action=`auth.login`/`auth.logout`/`auth.loginFailed`）。保留 `logs` 表兼容历史查询，新登录事件双写或迁移。

### 1.5 合规导出
`server/modules/audit/routes/auditRoutes.ts`：
- `GET /audit/logs` 分页查询（受 tenant 隔离）。
- `GET /audit/logs/export?from=&to=` 导出 CSV/Excel（复用 `server/utils/exportExcel.ts`），导出动作本身记一条 audit。

## 步骤 2：文件存储抽象

### 2.1 接口
`server/modules/storage/StorageProvider.ts`：
```ts
export interface StorageProvider {
  put(key: string, buffer: Buffer, opts?: { contentType?: string }): Promise<{ url: string; size: number }>
  get(key: string): Promise<Buffer>
  delete(key: string): Promise<void>
  signedUrl?(key: string, expireSec: number): Promise<string>
}
```

### 2.2 实现
- `providers/LocalStorageProvider.ts`：封装现有 `server/controllers/uploadController.ts` 的本地逻辑（按日期分目录，存 `server/uploads/`）。
- `providers/S3Provider.ts`：依赖 `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner`，支持 MinIO（设 endpoint + forcePathStyle）。
- `providers/OssProvider.ts`：阿里 OSS（`ali-oss`）。

工厂 `storageFactory.ts`：按 `settings` 表的 `storage_provider` 配置（local/s3/oss）+ 租户级覆盖返回实例。默认 local。

### 2.3 改造上传
修改 `server/controllers/uploadController.ts`：
- `uploadFile`：multer 用 memoryStorage，拿到 buffer 后调 `storageProvider.put(key, buffer)`，返回对外可访问 url。
- `key` 命名：`tenantId/yyyyMMdd/uuid.ext`（含租户隔离前缀）。
- 文件元数据表（现有 listFiles 用的存储）改为记录 `provider + key + url + size + tenantId`。
- `removeFile`：调 `provider.delete(key)` + 删元数据。

### 2.4 配置
`settings` 种子加 `storage_provider=local`、`storage_s3_*` 空配置。租户管理员可在设置页切换（M3 风格的 SsoSettings 类似页面）。

> 引入新依赖 `@aws-sdk/client-s3`、`ali-oss` 在 `server/package.json` 显式列出。

## 步骤 3：分布式任务队列（BullMQ）

### 3.1 背景
`server/utils/scheduler.ts` 用 `node-cron` 进程内调度，多实例（K8s 多副本）下每个实例都会触发同一 cron，导致重复执行。BullMQ 的 repeat job 在多实例下只一个 worker 抢到。

### 3.2 引入
`server/package.json` 加 `bullmq`。复用 `server/config/redis.ts` 连接。

### 3.3 队列封装
`server/modules/queue/index.ts`：
```ts
// queues: mail, workflow-trigger, report, usage-aggregate, audit-flush
export const queues = {
  mail: new Queue('mail', { connection }),
  workflow: new Queue('workflow', { connection }),
  ...
}
// worker 注册器：在 app 启动时按进程角色（web/worker）决定是否起 worker
```

### 3.4 改造 scheduler
`server/utils/scheduler.ts`：
- `node-cron` 仅用于"注册 BullMQ repeat job"（`queue.add(null, { repeat: { cron } })`），不再直接执行业务。
- 现有定时任务（`tasks` 表）的执行函数迁移为 BullMQ worker handler。
- 手动触发（`taskController` 的"立即执行"）改为 `queue.add(jobName, payload)`。

### 3.5 邮件/报表/用量聚合迁移
- `server/utils/mailer.ts` 的发送改为投递 `mail` 队列。
- M2 的用量日聚合：`usage-aggregate` repeat job（每日 00:05）把 Redis 计数落库。
- 工作流定时触发（M5a 超时/定时节点）走 `workflow` 队列。

### 3.6 部署
- 单进程模式：web + worker 同进程（开发/小部署）。
- 生产：建议拆 `worker` 进程（`server/scripts/worker.ts`），K8s 用 Deployment 单独跑 worker 副本。

## 步骤 4：密钥轮转

### 4.1 JWT 双验签
修改 `server/config/index.ts`：
- `jwt.secret`（current）保留；新增 `jwt.previousSecret`（可选）。
- `server/middleware/auth.ts:26`：`jwt.verify` 改为先用 current，失败再用 previous 验签（验签期，如 7 天）。
- 签发永远用 current。

### 4.2 配置项
`server/.env.example`：`JWT_SECRET`（current）、`JWT_SECRET_PREVIOUS`（轮转期旧值，留空表示无）。`config.app.encryptionKey`（M3 IdP 加密用，缺失则启动报错）。
